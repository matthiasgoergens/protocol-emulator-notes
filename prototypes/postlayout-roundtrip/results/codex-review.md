## Findings

1. **High — a disconnected or incorrectly clocked flip-flop can still pass the behavioural comparison.**  
   [sim.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/sim.ml:308) updates every flip-flop on every simulated cycle without using `f.clk`. [check.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/check.ml:122) checks that each clock net traces back to the clock port through buffers or inverters, but does not check the clock pin’s polarity or that the extracted cell is rising-edge-triggered. A falling-edge flip-flop, or one with the wrong clock polarity, can therefore be modelled as if it sampled on the expected edge. **False pass:** a clock connectivity or edge-polarity fault may escape lockstep; the structural trace does not establish clock-edge correctness.

2. **High — signal connectivity through an unrecognised conductor layer is omitted.**  
   [extract.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/extract.ml:19) recognises only seven metal layers, with a fixed set of via layers at lines 25–28. The extractor does not validate that the routed block uses only those layers and vias. If a real connection uses a layer or via absent from these tables, the extractor can split one physical net into separate extracted nets; if the resulting split still has one driver and no floating input, structural checks may pass, and behaviour can pass for faults not exercised by the simulations. **False pass:** unsupported routing is silently ignored. The review should verify that the actual GDS uses only the enumerated layer/datatype combinations.

3. **High — lockstep can compare no outputs and report agreement.**  
   [seq_lockstep.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/seq_lockstep.ml:1448) and [generic_lockstep.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/generic_lockstep.ml:48) derive comparisons solely from `Cyclesim.outputs`; neither rejects an empty output list. With no recognised RTL outputs, each run records zero mismatches. The structural port check can still be called independently, but zero compared outputs provide no behavioural evidence. **False pass:** a no-op comparison can be reported as agreement.

4. **Medium — the GDS parser does not validate record lengths before advancing.**  
   [gds.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/gds.ml:123) reads each record length and advances by that length at line 207 without checking that it is at least four bytes or remains within the file. A malformed or truncated GDS can make the parser loop without advancing, or read past the buffer. This is a tool robustness bug rather than a demonstrated valid-layout connectivity bypass. **False alarm / tool failure:** malformed input may hang or crash instead of producing a clear rejection.

5. **Medium — the planted-fault controls can classify changed connectivity as “no effect.”**  
   [roundtrip_check.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/roundtrip_check.ml:96) decides whether a mutation affected connectivity solely by comparing `nnets`. A cut or short can change which pins and ports share nets while leaving the number of nets unchanged. Such a fault is excluded from the caught/uncaught tally at line 101. **False alarm in the controls’ report:** the mutation may have changed connectivity, but the control labels it “NO EFFECT ON CONNECTIVITY,” so the planted-fault results do not establish sensitivity to that fault.

6. **Medium — the `check` command does not run lockstep.**  
   [roundtrip_check.ml](/home/matthias/prog/janestreet/emulator-wt-postlayout-roundtrip/prototypes/postlayout-roundtrip/roundtrip_check.ml:38) builds a simulator, then exits based only on `report.errors` at lines 42–44. It never compares that simulator’s outputs against RTL. **False pass if this command is treated as the round-trip check:** it can print `STRUCTURE CLEAN` without any behavioural comparison. The separate lockstep executable must be run and its result included for the combined claim to apply.

I did not modify files or run a build. The actual GDS and invocation results were not included, so I could not establish whether unsupported layers are present or whether the lockstep output set is nonempty in this run.
