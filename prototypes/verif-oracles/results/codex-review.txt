     4	   monoid homomorphism once each value is paired with its length. The derivation and the code

     8	   degree w; [poly] holds P without its x^w term, as the CRC catalogue writes it. Feed the message
     9	   bits m_1 .. m_n (in transmission order: MSB first, or LSB first for a reflected CRC) into the

    16	   and R(0, b) = R(s, b) + s * x^|b|, so with s = init:

## High

- **Hazard checker misses unbounded failure loops.** [`hazard.ml:200-209`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/hazard/hazard.ml:200) follows only `JMP` and `NOP`; any other instruction on the failure path is called `Bounded`. More directly, it returns `Bounded` after eight steps, even if the ninth reaches the wait again. A reachable `WAITC` whose failure target loops through nine NOPs back to itself is therefore misclassified. This breaks the “unbounded only when its failure path returns to itself” claim.

- **The CRC result does not establish coverage of every CRC variant claimed.** [`crc_oracle.ml:50-58`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/crc/crc_oracle.ml:50) tests the finite `Refs.catalogue`, and [`crc-maths.txt:9-15`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/results/crc-maths.txt:9) lists seven CRCs. That evidence does not cover a catalogue entry with `refin <> refout`. The planted `Zlib_formula` is a deliberately incorrect expression at [`crc_combine.ml:83-87`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/crc/crc_combine.ml:83); calling it “exactly zlib’s formula generalised” overstates what this check demonstrates. ## Medium

- **The fixed Ethernet firmware can report on an end-of-stream underrun.** At [`eth_fixed.ml:44-47`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/stall/eth_fixed.ml:44), `Jnz "under_real"` selects the end-of-stream `Halt` only when the count is zero. But the earlier `WAITC` branches to `under_real` on invalid host input at [`eth_fixed.ml:34`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/stall/eth_fixed.ml:34). If the last byte has been consumed and the next byte is not valid, this path reaches `Halt` without another `IN`; the shown code does not substantiate the unconditional “end-of-stream path never reports” claim.

- **The host model’s valid/ready claim depends on the active thread staying fixed while stalled.** The model computes `valid` from `next.(t)` and `avail.(t)` for the currently executing thread at [`eth_stall.ml:116-120`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/stall/eth_stall.ml:116), then advances that thread’s availability only after `host_in_ready` at [`eth_stall.ml:128-131`](/home/matthias/prog/janestreet/emulator-wt-verif-oracles/prototypes/verif-oracles/stall/eth_stall.ml:128). That supports persistence while the same thread is stalled, but not a general four-thread valid/ready guarantee if the core can change threads during the stall. The displayed run does not demonstrate that case.
